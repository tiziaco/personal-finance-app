# Analytics Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/analytics`, four tabs of honest, labelled figures drawn from the analytics
routes PR #16 completed.

**Architecture:**

- A client page under `app/(dashboard)/analytics/` renders `AnalyticsPage`, which holds the
  `@app/ui/tabs` and the URL state. Base UI unmounts an inactive tab's panel, so a tab's
  queries run only once it is opened.
- Each tab is a self-contained component that owns its queries, skeleton, empty and error
  states.
- Pure helpers do formatting and chart mapping only, and each is unit tested.
- The server computes every figure. The page does no arithmetic on money or percents.

**Tech Stack:** Next.js 16, React, TanStack Query hooks generated by orval
(`@app/api-client`), recharts through `@app/ui/chart`, Base UI tabs, Vitest and Testing
Library.

**Spec:** `.superpowers/specs/2026-10-16-analytics-page-design.md`. Read it first: §4 holds
the page-wide rules and §5 each tab's contents. The field meanings are the generated types
under `web-app/packages/api-client/src/generated/types/`.

## Global Constraints

- **Ownership: edit only these:**
  - `web-app/apps/web/src/app/(dashboard)/analytics/`;
  - `web-app/apps/web/src/components/analytics/`;
  - `web-app/apps/web/src/lib/hub-nav.ts`;
  - the docs in Task 9.
- **Never edit:**
  - `components/dashboard/`, `server/` or `packages/api-client/src/generated/`;
  - any `@app/ui` primitive. A new primitive goes through the coordinator first.
- **Imports allowed from `components/dashboard/`:** `SectionError`
  (`section-error.tsx`), `ANALYTICS_STALE_TIME` (`home-dashboard.tsx`) and `formatMonth`
  (`month.ts`).
- **No arithmetic on server figures.** The page may only:
  - format numbers;
  - map slugs to labels;
  - turn a decimal string into a `Number` for chart geometry;
  - choose colour, arrow and wording from a sign or a null;
  - format dates (is a date a 1st, or a month's last day).

  The one exception, flagged in the spec: `formatIndex` shows `index − 100`.
- **Null percent:** shown as "—", or as the given reason. Never shown as 0.
- **Every query** passes `query: { staleTime: ANALYTICS_STALE_TIME, meta: { silentError: true } }`.
- **Loading, error and data:** a section shows a skeleton while it has no data; with no
  data and an error, `SectionError` with a retry. Once data exists, a failed background
  refetch keeps showing it (the dashboard's rule).
- **Money and colour:**
  - Money goes through `formatAmount` from `@/components/transactions/format`.
  - Category labels come from `useCategories().label` (`@/components/transactions/use-categories`).
  - Income and expense series use `var(--chart-income)` and `var(--chart-expense)`.
  - A change is coloured by good or bad, never by direction alone. An arrow and words
    always go with the colour.
- **Mobile and dark mode:**
  - Tables become card lists below `sm`.
  - Nothing scrolls the page sideways at 375 px.
  - Every colour comes from a theme token.
- **Commands and commits:**
  - Run the commands from `web-app/`: `pnpm exec vitest run <path>` for one file,
    `pnpm test` for the suite. Run `make check-web` from the repo root before the last
    commit.
  - Each commit message starts with "Analytics page: ".

## Review Focus

1. **A user with no transactions at all.** Every tab shows its empty state: no "€0.00",
   no "▲ 0.0%", no empty chart axes. Owned by Tasks 4–7, an "empty response" test each.
2. **Only the month in progress has data** (the server's fallback). Then:
   - the label reads "1 – 16 Oct 2026"-style;
   - the month-to-date strip is hidden;
   - `latest_month` is null and its section is hidden;
   - every month-over-month value is a gap.

   Owned by Task 5 (a strip hidden test), Task 1 (a label test).
3. **Spending more than earning.** A negative `net`, `average_monthly_net` and
   `savings_rate_pct` render with a minus sign, in the bad tone, never as a positive or
   "—". Owned by Task 5 (a negative net test).
4. **A hand-edited or stale URL** (`?tab=nope&flow_months=7&trend_months=abc`). Each value
   falls back to its default, and nothing throws. Owned by Task 2 (a fallback test).
5. **A background refetch fails after data loaded.** The data stays and no error card
   replaces it. Owned by Task 4 (a refetch-error test), the pattern Tasks 5–7 copy.

```ts
const d = (iso: string) => { const [y, m, day] = iso.split("-").map(Number); return new Date(y, m - 1, day) }
const range = (o: Intl.DateTimeFormatOptions, a: string, b: string) =>
  new Intl.DateTimeFormat(undefined, o).formatRange(d(a), d(b))
const MONTHS = { month: "short", year: "numeric" } as const
const DAYS = { day: "numeric", month: "short", year: "numeric" } as const

describe("formatPeriod", () => {
  it("names one whole month", () =>
    expect(formatPeriod("2026-09-01", "2026-09-30")).toBe(formatMonth("2026-09")))
  it("ranges whole months by month", () =>
    expect(formatPeriod("2026-07-01", "2026-09-30")).toBe(range(MONTHS, "2026-07-01", "2026-09-30")))
  it("ranges across a year by month", () =>
    expect(formatPeriod("2025-11-01", "2026-01-31")).toBe(range(MONTHS, "2025-11-01", "2026-01-31")))
  it("gives days for the month in progress", () =>
    expect(formatPeriod("2026-10-01", "2026-10-16")).toBe(range(DAYS, "2026-10-01", "2026-10-16")))
  it("gives days when the data starts mid-month", () =>
    expect(formatPeriod("2026-09-12", "2026-10-31")).toBe(range(DAYS, "2026-09-12", "2026-10-31")))
  it("treats 29 Feb as a month end", () =>
    expect(formatPeriod("2028-02-01", "2028-02-29")).toBe(formatMonth("2028-02")))
  it("is null when the period is empty", () => expect(formatPeriod(null, null)).toBeNull())
})

describe("changeTone", () => {
  it("spending up is bad, down is good", () => {
    expect(changeTone(12, "spend")).toBe("bad"); expect(changeTone(-3, "spend")).toBe("good")
  })
  it("income up is good, down is bad", () => {
    expect(changeTone(4, "income")).toBe("good"); expect(changeTone(-4, "income")).toBe("bad")
  })
  it("zero and null are neutral", () => {
    expect(changeTone(0, "spend")).toBe("neutral"); expect(changeTone(null, "income")).toBe("neutral")
  })
})

describe("formatIndex", () => {
  it("above", () => expect(formatIndex(135)).toBe("35% above a typical month"))
  it("below", () => expect(formatIndex(88.4)).toBe("12% below a typical month"))
  it("typical", () => expect(formatIndex(100.3)).toBe("a typical month"))
  it("no data", () => expect(formatIndex(null)).toBe("no data yet"))
})

describe("formatPct", () => {
  const one = (n: number) =>
    `${new Intl.NumberFormat(undefined, { minimumFractionDigits: 1, maximumFractionDigits: 1 }).format(n)}%`
  it("one decimal, sign kept", () => {
    expect(formatPct(8.24)).toBe(one(8.24))
    expect(formatPct(-12)).toBe(one(-12))
  })
})

describe("formatDayRange", () => {
  const DM = { day: "numeric", month: "short" } as const
  it("days 1 to the given day", () =>
    expect(formatDayRange("2026-10", 16)).toBe(range(DM, "2026-10-01", "2026-10-16")))
  it("clamps to a shorter month", () =>
    expect(formatDayRange("2026-09", 31)).toBe(range(DM, "2026-09-01", "2026-09-30")))
})
```

- [ ] **Step 3: Implement `format.ts`**

`formatPeriod`:

- Parse the dates with `new Date(y, m - 1, d)` (local time, no UTC shift).
- An end is "on a boundary" when `dateFrom`'s day is 1 and `dateTo`'s day equals
  `new Date(y, m, 0).getDate()`.
- Both ends on boundaries:
  - the same month gives `formatMonth("YYYY-MM")`;
  - otherwise, `formatRange` with `MONTHS`.
- Otherwise, `formatRange` with `DAYS`.

`formatIndex` rounds `index − 100` to a whole number; a result of 0 gives "a typical
month". `formatPct` uses `Intl.NumberFormat(undefined, { minimumFractionDigits: 1,
maximumFractionDigits: 1 })` with "%" appended.
