# Step 6 Insights Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI-written insights about the last finished month against the user's usual, plus the
month so far — stored per user, served by two routes, shown on `/insights` and in a home callout —
and the home page's month-to-date card.

**Architecture:** A new `app/modules/insights/` stores one set per user (JSONB) and exposes
`GET /insights` (read only, with a freshness status) and `POST /insights/generate`. One function,
`figures.py`, is the only code that reads `analytics_service` results; it hands plain JSON to a
one-call agent in `app/agents/insights/` (labeller pattern, `structured_llm_service` + `ask_json`).
The web reads the set with generated hooks; the page generates on arrival when the set is missing
or stale, the callout never does.

**Tech Stack:** FastAPI, SQLModel, Alembic, import-linter, pytest (testcontainers Postgres);
Next.js 16, TanStack Query via orval-generated hooks, Base UI, Vitest + Testing Library.

**Spec:** `.superpowers/specs/2026-10-16-insights-design.md` (read it; this plan argues from it).
**Brief:** `.superpowers/BRIEF.md` §3 (ownership and conditions bind every task).

## Global Constraints

- No file in the diff imports `llm_service`; the agent uses `structured_llm_service`. Not registered in `AGENT_REGISTRY`.
- No edit under `server/app/modules/analytics/`, `app/agents/{factory.py,__init__.py,base,chatbot,shared}`, `app/integrations/llm/`.
- `app.agents` imports no module (R2): the agent takes plain values only.
- R6 becomes `"app.modules.conversation | app.modules.insights"` above `"app.modules.analytics"`; `conversation` does not import `insights`.
- `TransactionService`'s existing method signatures and the transaction routes stay as they are (step 7 reads them); the one write-path change is the delete-all event (orchestrator-approved, 16 Oct 2026).
- Only `figures.py` names an analytics response field. Authority for those fields: `gh pr view 16`.
- No prompt wording, severity guidance or threshold tuned against a run before Task 9's real-figures check.
- Sections: `spending · recurring · savings · anomalies · comparisons`. Severities: `info · low · medium · high · critical`. Periods: `month · month_to_date`. Statuses: `no_data · none · stale · fresh`.
- At most 10 insights; 0 is valid. A `month_to_date` insight's severity is capped at `medium`.
- Prose amounts: `€` before the number, whole euros with comma thousands (`€1,240`), cents only under €10 (`€4.99`).
- Web: generated hooks and types only (`@app/api-client`); amounts through `formatAmount`; Base UI `render` prop, not `asChild`.
- `summary-cards.test.tsx` already carries analytics-figures' two fixture lines — don't add them again.
- Sidebar order: Home, Transactions, Analytics (5b adds), Insights, Chat.

## Review Focus

1. **A month rolls over with no new data** (set generated 28 Oct; opened 3 Nov) → the reference month has moved to October, so the set must read `stale`. Spec §4 says stale = data changed; this plan adds "or `generated_at` is in an earlier UTC calendar month than today" — the user is told at hand-over. Test in Task 5.
2. **Auto-generate on arrival fails** → the page must not loop: one automatic attempt per arrival, then the error and a retry button; previous cards stay. Test in Task 6.
3. **The model returns a link to a merchant it was not given, a category that is not a slug, or 11 insights** → the bad link is dropped (card kept); more than 10 fails the answer (one retry, then 503). Tests in Task 3.
4. **Only soft-deleted rows remain** (user deleted every transaction one by one) → `no_data`, no model call, no cards shown. Test in Task 5.
5. **`month_to_date` change pcts are null** (previous month only partly in the data) → the month-to-date card shows figures with no comparison; the model is not handed a comparison. Tests in Tasks 4 and 8.
